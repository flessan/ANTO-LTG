01 / API

API statis, tanpa autentikasi.

Endpoint awal menyajikan JSON publik. Versi API ditulis di URL agar perubahan berikutnya bisa dikelola dengan jelas.

GET /api/v1/apps.jsonGET /api/v1/drivers.jsonGET /api/v1/bundles.jsonGET /api/v1/tools.json

Software Bundler memakai field opsional `winget_id` untuk menghasilkan skrip lokal; ID paket dan kompatibilitas harus diperiksa sebelum penggunaan. Belum ada jaminan uptime atau rate limit formal pada tahap MVP. Jangan gunakan katalog ini sebagai satu-satunya sumber untuk tindakan kritis.

02 / SCHEMA

Data kecil, konsisten, bisa divalidasi.

Setiap item memiliki ID stabil, nama, deskripsi, sumber HTTPS, dan status tinjauan. Metadata kompatibilitas harus didukung bukti; kolom kosong atau “not_reviewed” berarti belum dipastikan.

{
  "schema_version": "1.0.0",
  "updated_at": null,
  "items": [
    {
      "id": "contoh-aplikasi",
      "name": "Nama aplikasi",
      "category": "utility",
      "description": "Deskripsi faktual aplikasi.",
      "publisher": "Penerbit",
      "source_url": "https://publisher.example/",
      "winget_id": "Publisher.Package",
      "source_kind": "publisher_page",
      "verification_status": "pending_review",
      "windows_compatibility": "not_reviewed",
      "architectures": [],
      "license": "Periksa ketentuan penerbit",
      "notes": "Kompatibilitas belum ditinjau."
    }
  ]
}

Catatan: contoh tersebut hanya ilustrasi struktur. Item katalog yang dipublikasikan harus mengikuti field wajib di folder catalogs/.

03 / CONTRIBUTE

Kontribusi melalui pull request.

Tambahkan item di file JSON yang sesuai, jangan kirim installer atau firmware secara langsung, lalu jalankan validasi sebelum membuka pull request.

1

Fork repository
Gunakan ID lowercase-kebab-case yang stabil.

2

Tambahkan metadata
Sertakan sumber HTTPS dan catatan kompatibilitas yang dapat dirujuk.

3

Jalankan validator
npm run validate

4

Ajukan pull request
Jelaskan sumber dan bukti yang mendukung perubahan.

Buka GitHub ↗

Tautan repository akan diperbarui setelah repo resmi dibuat.

04 / TRUST & SAFETY

“Resmi” dan “aman” bukan label otomatis.

Validator memeriksa struktur data dan URL HTTPS, bukan malware atau kebenaran klaim. Status verified hanya boleh diberikan setelah peninjauan manusia dengan catatan tanggal dan bukti yang jelas.

  • Utamakan halaman vendor atau penerbit asli.
  • Hindari direct-link mirror yang tidak dapat dipertanggungjawabkan.
  • Jangan menyimpan kredensial, token, atau informasi pribadi di katalog.
  • Laporkan URL mencurigakan dan entri yang sudah ditarik oleh penerbit.
